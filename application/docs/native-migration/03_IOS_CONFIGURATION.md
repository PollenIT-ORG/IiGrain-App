## 5. Google Maps — the key-delivery chain (iOS's most intricate piece)

The Google Maps iOS SDK has **no Info.plist convention** — it must be handed its key in code, via
`GMSServices.provideAPIKey()`, **before the first `GMSMapView` is created**. The SDK is a
process-wide singleton with no retry: if it is unkeyed when the first map view is instantiated,
every map in the session stays blank.

The project solves this with a five-hop chain:

```
application/.env  (or $MAPS_API_KEY)
      │  parsed by resolve_maps_api_key() at `pod install` time
      ▼
ios/Config/Env.generated.xcconfig        ← GENERATED, GITIGNORED
      │  #include?'d from the CocoaPods-generated Pods-iiGrain.{debug,release}.xcconfig
      ▼
$(MAPS_API_KEY)                          ← an Xcode BUILD SETTING
      │  expanded by Xcode into Info.plist values at build time
      ▼
Info.plist → GMSApiKey
      │  read at launch
      ▼
AppDelegate.configureGoogleMaps() → GMSServices.provideAPIKey(apiKey)
```

### Why each hop exists

| Hop | Reason |
|---|---|
| `.env` → xcconfig | Native Swift cannot read `.env`; `react-native-dotenv` only rewrites `@env` imports inside the JS bundle |
| Generated file, not `project.pbxproj` | Keeps the secret out of version control — `project.pbxproj` is committed, `ios/Config/Env.generated.xcconfig` is gitignored |
| `#include?` (optional include), appended **last** | Appended last so the assignment wins over anything above; optional so a fresh clone that has not run `pod install` still builds |
| Re-appended every `pod install` | CocoaPods regenerates the aggregate xcconfigs each run, wiping the include |
| Info.plist as transport | `$(VAR)` in Info.plist **values** is expanded from build settings at build time |

### Implementation

**`ios/Podfile`** — `resolve_maps_api_key` (env var → `.env` → `''`), `write_maps_xcconfig`, and a
`post_install` hook that walks `installer.aggregate_targets` and appends the `#include?` line to
every configuration's xcconfig.

**`ios/iiGrain/Info.plist`**

```xml
<key>GMSApiKey</key>
<string>$(MAPS_API_KEY)</string>
```

**`ios/iiGrain/AppDelegate.swift`**

```swift
private func configureGoogleMaps() {
  let apiKey = (Bundle.main.object(forInfoDictionaryKey: "GMSApiKey") as? String)?
    .trimmingCharacters(in: .whitespacesAndNewlines) ?? ""
  guard !apiKey.isEmpty else {
    NSLog("[Maps] GMSApiKey is empty — maps will render blank. …")
    return          // deliberately does NOT crash
  }
  GMSServices.provideAPIKey(apiKey)
}
```

called as the **first statement** of `didFinishLaunchingWithOptions`.

### Failure mode by design

A missing key **never fails the build and never crashes** — `GMSApiKey` resolves to empty and
`AppDelegate` logs a loud warning. Rationale in-file: non-map work (unit tests, simulator runs by
developers without Maps Platform access) must never be blocked by a missing secret.

### ✅ Contrast with Android

Unlike Android — where the key is a **hardcoded literal in the committed
`AndroidManifest.xml`** — the iOS side keeps the key entirely out of version control and the
mechanism is **live and correct**. Reproduce this chain faithfully.

### Current state in this working tree

`ios/Config/` **does not exist** — `pod install` has not been run on this machine (which is Windows;
iOS builds happen elsewhere). It will be created on the first `pod install`.

## 12. `Podfile`

**Path:** `ios/Podfile` — three substantive customisations over the RN template.

### 12.1 🔴 `RCT_USE_PREBUILT_RNCORE = '0'`

```ruby
ENV['RCT_USE_PREBUILT_RNCORE'] = '0'
```

**The highest-risk single line in the iOS config.** The documented reasoning:

* RN 0.84 defaults to `RCT_USE_PREBUILT_RNCORE=1`, which downloads a **Release**-built
  `React.xcframework` compiled with `NDEBUG`. Its debug-only symbols are compiled out — `nm` on the
  simulator slice finds **zero** occurrences of `ShadowNode::getDebugName`,
  `BaseViewProps::getDebugProps`, or `Sealable`'s ctor/dtor.
* Third-party Fabric pods compiled in Debug (`RNScreens`, `RNSVG`, `RNGestureHandler`,
  `RNReanimated`, `RNDateTimePicker`) still reference those symbols → a Debug simulator build dies
  with *"Undefined symbols for architecture arm64"*.
* Release **device archives link fine**, which is why only local development was broken.

Setting it to `0` builds core from source, making Debug and Release self-consistent.
**Cost:** the first build after each `pod install` is considerably slower.

> Omit this line in the fresh project and iOS Debug simulator builds fail with an undefined-symbols
> link error that reads like a corrupted Pods install. Budget hours if it is lost.

### 12.2 🔴 `react-native-maps/Google` subspec

```ruby
pod 'react-native-maps/Google', :path => '../node_modules/react-native-maps'
```

Declared **before** `use_react_native!`. Google Maps on iOS is **opt-in**: `react-native-maps`'
default `Maps` subspec compiles Apple MapKit only, and the podspec's build script then defines
`HAVE_GOOGLE_MAPS=0`, so `provider="google"` **silently falls back to Apple Maps**.

Declaring `/Google` pulls in the `GoogleMaps` + `Google-Maps-iOS-Utils` pods and flips the flag to
`1`, so iOS and Android render the same tiles and honour the same JSON map style.

> **Silent-failure risk:** if this line is missed, the app still builds and maps still appear — as
> **Apple Maps**, ignoring the custom map style. Easy to miss in review.

### 12.3 Maps-key xcconfig generation

`resolve_maps_api_key`, `write_maps_xcconfig`, and the `post_install` xcconfig-include injection.
Fully described in §5.

### 12.4 Standard Podfile elements


## 15. Build phases

The `iiGrain` target has **7 phases, in this exact order**:

| # | Phase | Type | Notes |
|---|---|---|---|
| 1 | `[CP] Check Pods Manifest.lock` | Shell script | CocoaPods-generated; diffs `Podfile.lock` against `Pods/Manifest.lock` |
| 2 | `Sources` | Compile | `AppDelegate.swift` — **the only source file** |
| 3 | `Frameworks` | Link | `libPods-iiGrain.a`; `JavaScriptCore.framework` is referenced in the project |
| 4 | `Resources` | Copy | 7 items — see below |
| 5 | `Bundle React Native code and images` | Shell script | ⚠️ **hand-authored** — see below |
| 6 | `[CP] Embed Pods Frameworks` | Shell script | CocoaPods-generated |
| 7 | `[CP] Copy Pods Resources` | Shell script | CocoaPods-generated |

> **Ordering matters:** the RN bundle phase (5) runs **after** `Resources` (4) and **before** the
> CocoaPods embed/copy phases (6, 7). Reproduce this order.

### Fonts

| Aspect | Detail |
|---|---|
| Declared in | `Info.plist` → `UIAppFonts` (5 entries) |
| Copied by | `PBXResourcesBuildPhase` (the 4 Inter `.ttf` files) |
| `PBXFileReference` paths | `../src/assets/fonts/Inter-*.ttf` — **referenced from `src/`, not copied into `ios/`** |
| `MaterialCommunityIcons.ttf` | Declared in `UIAppFonts`; delivered by the `RNVectorIcons` pod's resource bundle, **not** a project file reference |
| Bookkeeping | `ios/link-assets-manifest.json` — SHA-1s of the four Inter files (identical to the Android manifest) |

> ⚠️ **iOS resolves these fonts by PostScript name, not filename** — a known and documented trap in
> this project (see the project memory note on Inter typography). The four files are the "18pt"
> Inter cut whose PostScript names are `Inter18pt-Regular`, `Inter18pt-Medium`,
> `Inter18pt-SemiBold`, `Inter18pt-Bold`, while Android resolves the same files by filename
> (`Inter-Bold`, …). This asymmetry is handled in JS (`src/theme/typography.ts`) and is out of scope
> here, but it means **the exact same .ttf files must be used** — substituting a different Inter cut
> silently breaks iOS typography while leaving Android fine.

**Migration action:** run `npx react-native-asset` rather than hand-adding font references, so the
`PBXFileReference` paths (`../src/assets/fonts/…`), the Resources phase membership, the `UIAppFonts`
array and `link-assets-manifest.json` all stay mutually consistent.

## 22. iOS-side risks to resolve before migrating

1. 🔴 **`RCT_USE_PREBUILT_RNCORE=0` must survive.** Its absence produces an undefined-symbols link
   error that reads like a broken Pods install. → §12.1
2. 🔴 **The `react-native-maps/Google` subspec fails silently.** Maps still render — as Apple Maps,
   ignoring the custom style. Verify by confirming `import GoogleMaps` resolves. → §12.2
3. 🔴 **Keychain continuity depends on team + bundle ID.** Changing either logs out every existing
   tester. → §9
4. 🔴 **Add no capabilities and no entitlements file.** The current app has none; adding Push (even
   by an accidental Xcode capability click) changes signed entitlements and can fail validation.
   → §8
5. 🔴 **`CURRENT_PROJECT_VERSION` must go to ≥ 10.** Build 9 is already consumed. → §2
6. 🟡 **`Podfile.lock` is gitignored** — pod versions are not currently pinned across machines.
   Recommend committing it in the fresh project (a separate improvement, not part of preserving
   identity). → §13
7. 🟡 **Only `en` is a known region** and there is no localisation; keep it that way to avoid
   changing App Store metadata behaviour.
